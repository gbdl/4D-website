# A small companion for two frozen metric states

This directory is an inspectable reproduction of **R4-022 joint-best** (`local`, step 402034) and **R4-087 joint-best** (`compatible`, step 26838). It is a bounded companion to this first experiment. It does not train a model, implement a search system, or certify a manifold-wide result.

The implementation is adapted from a separate reconstruction written from the mathematical notes. The bundled test values were saved by the original numerical implementation, rather than generated by the companion being tested. Their source-array hashes and exact row selections are in `fixtures/manifest.json`. Both models retain their physical normalization, with no historical factor 100.

## Install and run

From this directory, with Python 3.12:

```sh
python3.12 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -B check.py
.venv/bin/python -B check.py --metrics --output result.json
```

`check.py` checks analytic metrics and reconstructs curvature from the saved jets without re-evaluating the neural metrics. `--metrics` additionally differentiates each frozen neural metric and compares metric values, first derivatives and second derivatives with the saved reference tensors. It runs the two models sequentially and restricts the process to one numerical CPU where supported. The first call in each chart compiles; warm calls reuse that compiled function. See `../verification/evaluator.json` for measured time and memory on the delivery machine, not a hardware-independent estimate.

JAX and NumPy are the direct numerical dependencies. JAX additionally installs its CPU runtime, SciPy, `ml_dtypes` and `opt_einsum`; the companion imports no original research repository or training package. A tested environment lock is in `requirements-lock.txt`. No GPU is required.

## One point

```sh
.venv/bin/python -B -m metric_demo --metric local --chart ordinary --point 1.5 0.5 0.5 0.5
.venv/bin/python -B -m metric_demo --metric compatible --chart core --point 0 0 0 0 --diagnostics
```

The Python interface is equally small:

```python
from metric_demo import load_metric
metric = load_metric('local')
g = metric.metric([1.5, .5, .5, .5], chart='ordinary')
jet = metric.jet([0., 0., 0., 0.], chart='core', order=2)
result = metric.diagnostics([0., 0., 0., 0.], chart='core')
```

- `ordinary`: `(z,x1,x2,x3)`, with `0<z<r_j`. At the exact filled tip, use `core`.
- `core`: `(U,V,tau1,tau2)`, restricted to the actual image of the coordinate domain. At `U=V=0`, validity uses projection of the horizontal box along the filled slope.
- `cusp`: `(t,X1,X2,X3)`, with `t>=1` and an integer `site` from 0 to 36. The native point must map into the displayed domain. Use the centre and cusp-class table in `fixtures/geometry.json`; site numbers must not be assumed to match another implementation.

The raw field is evaluated at its original coordinates: **no periodic folding is applied to it**. The compatible construction uses the periodic and reflection prescription documented in the note. Invalid coordinates raise an exception. Nonfinite tensors or loss of numerical positivity also raise an exception; points are never silently dropped.

Outputs are float64 physical tensors. Derivatives use `dg[i,j,k] = partial_k g_ij` and `d2g[i,j,k,l] = partial_k partial_l g_ij`. Diagnostics return `E=||Ric+3g||_g/6`, scalar curvature `S`, `(S+12)/12`, the coordinate matrix condition number and explicit validity. `E` is not distance to an exact solution. A condition number is coordinate-dependent.

## What the checks cover

The small fixture contains 12 matched points per construction: body, cap, exact core, reflection support, and transition/deep examples in each of the four unfilled cusps. It is selected for coverage, not to estimate regional error statistics. Two further saved interface points demonstrate one vertical and one spherical pair. At those points, the test reconstructs the induced metric and extrinsic curvature using the saved embeddings and canonical conormals, and compares fresh metric/derivative values when `--metrics` is supplied.

The 37 site centres, cusp classes, frames and four cusp lattices are checked against a separately saved geometry table. NumPy curvature contractions use explicit index loops independent of the JAX contractions. Flat, hyperbolic, spherical and scaled-hyperbolic controls fix conventions. Deliberately wrong curvature signs, normalization and a nonzero-extrinsic-curvature normal sign are rejected. Inputs outside the domain, native-cusp points below `t=1`, and the singular ordinary tip are rejected.

The saved fixtures are cross-checks, not a proof. They do not reproduce the full face/ridge catalogue, establish uniform accuracy, or resolve the limitations discussed on the website.

## Provenance and licensing

`provenance.json` records source-kernel hashes, the original checkpoint hashes, evaluated steps, representation specifications and numeric-only export hashes. Parameter arrays are loaded with `allow_pickle=False`. The loader checks the export digest, shapes, dtype and finite values before constructing either metric.
